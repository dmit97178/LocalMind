## 一、功能需求

### 🟢 FR1 本地为主、云端兜底

**描述**：所有理解、记忆、常规执行在本地完成。云端仅作为本地模型决策后调用的外部工具，不是独立路由。云端的核心价值是**受控推理升级**——以更大上下文与更强推理处理本地小模型难以稳定完成的复杂任务（复杂推理、架构权衡、代码分析、长上下文综合），联网资料检索只是升级原因之一（`escalation_reason` 受限枚举，见 05 契约 §1.1/§2.5）。

**要求**：
- 本地系统是主控；本地模型负责理解、候选生成和结果整合；ControlPolicy 负责最终调度决策
- 云端模型注册为工具，和文件/Shell 操作地位相同
- 模型可提出是否咨询云端、提出候选上下文（`ConsultationProposal`），但不能直接调用云端、不能批准外发、不能扩大授权范围；最终是否调用由 ControlPolicy 结合用户指令与确定性规则裁决
- 隐私目标是分级授权而非永久零上下文：外发内容按来源与敏感级别分类（固定配置 / 用户派生实体 / 自由文本·代码·日志 / 秘密·凭据，四类不混淆），经本地脱敏策略与用户有限授权后按需外发
- 用户授权是「有限、不可扩大」的 grant——绑定任务/会话、云端提供商、目的、允许的数据类别或确切 payload、最大 sub-turn/预算与有效期；越界（新类别/新自由文本/任务切换/供应商变化/超预算/过期）必须重新确认；拒绝/取消/授权超时不发送也不消耗预算，网络尝试开始即消耗一轮，网络失败或入站拒绝不退款并进入冷却期；grant 仅复用同一任务的连续 sub-turn，不跨后续普通用户回合
- 至少提供三种隐私模式：严格（每次含用户内容外发均确认）、平衡（默认：同任务内有限 grant 可复用）、便捷（仅低风险结构化字段可由 PrivacyPolicy 签发同样有限、可审计的自动 grant；自由文本/代码/路径/日志仍确认）；用户“问云端”可跳过模型的效用建议，但不能跳过隐私策略与授权，用户“不要联网”拥有最高优先级
- 发给云端的不是原始上下文，而是本地分析后、经脱敏授权的结构化请求包；秘密/凭据绝不外发，允许以 `api_key: present` 等语义占位替代
- **凭据检测覆盖中文自然语言形态，且全链路单一真源（2026-09-24 安全边界变更，`05` §2.3c）**：秘密/凭据的检测判据**只有一处定义**，出站检查、授权 preview、审计事件、记忆落盘、异常文本全部委托同一实现，**不存在第二处自定义模式集**（配置中的模式键只允许追加，内建恒生效）。检测必须覆盖中文自然语言形态：`我的账号密码是123456`、`密码是青山绿水` 与 `api_key=sk-…` 同等处理，**不得**以「值区是中文形态」为由豁免。命中条件与作用域**只有一种模型**（2026-09-24 **第三轮重写**，`05` §2.3c.3）：**命中 = 凭据标签闭集成员 + 边界成分**，边界成分是显式分隔符（`= : ： ＝ 是 为 等于`）、空白（≥1 个空格/制表）、或紧邻的非 CJK 非空白字符（粘写形态），**全部与值无关**；**值区 = 标签之后到本行末尾的连续跨度**（去掉标签与值区之间的边界成分、strip 首尾空白），标签独占一行时**顺延一次**取下一个非空行；区内**不再切分、不筛形态**。判态只看两问：值区**为空** → 不可命中（后面没有内容、没有外发面）；值区**恰等于** `[已脱敏:secret]` → 不可命中（占位符显式自免疫 ⇒ 幂等）；值区**非空** → **可替换**（整个值区原地替换为 `[已脱敏:secret]`，字段名与分隔符保留，**出站与本地同源、同字面量、同一实现**）。**显式删除、不得回归的判据**：任何「值像不像值」的判断（是否含中文、是否含空白、是否含标点）一律不得参与命中或判态——`密码 abc123`（裸空格）、`密码是abc，青山绿水`（标签之后的整行）必须同样被替换；该删除是中文口令漏检的直接成因，**不得**以任何理由恢复。防误伤靠**标签闭集与标签侧边界条件**（拉丁标签要求右边界；CJK 标签**紧随 CJK 字符**时粘写判定不成立——`密码学`；紧随非 CJK 非空白字符时**照常触发**——`密码abc123`），**禁止**任何形态/语法豁免（否则 `系统密码是…` 一类会被误豁免）。**不含标签的普通数字陈述（`计数器是123456`）不得被误伤**；占位符必须幂等。**三条语法边界照实声明（是语法边界，不是形态豁免）**：标签与值之间**完全没有边界字符**的粘写（`密码青山绿水`，覆盖它会把 `密码学`/`密钥管理` 错认成凭据）、值在标签**之前**（`abc123 是我的密码`）、值**跨一个以上顺延行**——三者由既有的**无标签裸秘密检测层**兜底。**出一条与凭据无关的诚实拒绝**：某段脱敏后若只剩占位符、标签、分隔符、空白与标点（即已无任务语义），本地**拒绝该段外发**（拒绝比发送一个只能换来无效或杜撰回答的请求更诚实），记**固定原因文案、不含原值**，**不新增错误码、不新增事件枚举**。**已知代价照实登记**：`改密码是必要的`、`token 过期了` / `api_key 读不到`（拉丁标签 + 空白 + 中文技术句）一类会被整段替换并触发一次强制确认——它们与 `password 青山绿水`（真中文口令）字符级不可区分，**只能按口令处理**；这是为杜绝中文口令漏检而**有意选择的不对称取舍**（过度脱敏可见、可拒绝、有界；漏检不可见且即泄漏），**不得**通过重新引入形态豁免来消除；**代价的消解方向是提高标签侧选择性**，绝不回收值形态判据。授权门槛不因此降低：含凭据的输入仍计入升险源 ⇒ 强制用户授权，且授权后原值在 payload / 事件 / 审计 / 异常 / 记忆五面均不可检索
- 每次云端外发记录授权决策、grant 边界、外发字段类别/脱敏结果、预算消耗和拒绝原因；不得记录原始秘密、未授权原文或云端 analysis 原文
- 云端模型不直接面对用户，返回结果由本地模型整合后呈现
- **云端结果回流进记忆（2026-09-24）**：云端咨询的最终回复（含 followup 子回合结果与本地兜底串）与普通回合走**同一条** episode 写入链——必须能被后续轮次检索召回，不允许出现「上一轮刚拿到云端结论、下一轮短追问却召回不到」的连续性断裂。User 段 = **原回合用户输入**（`/cloud allow` 是控制指令，不入正文）；Assistant 段带**云端来源标记**（固定前缀、本地确定性生成、不由模型产出），使后续检索与再外发能区分「用户说过什么」与「云端模型返回过什么」。写回冻结原回合的 topic / intent 判定（**冻结快照由本地任务上下文承载**，不由授权挂起结构承载），**不为补写回重跑意图解析**。**每个云端任务恰好一条 episode，且只在终结时写**：产出授权确认提示的那一回合**不写**（临时提示不得进入语义记忆、会话摘要或项目摘要，否则同一输入会留下重复记录、且该提示会被当作系统回复参与检索）。**终结形态全枚举七种**（2026-09-24 第三轮补全）：成功收敛与 fallback 收敛**各补写唯一一条**；取消 / 授权失效 / 跨会话不匹配 / 被新输入取代 / **云端挂起追问**（云端本轮回复是追问、不是答案）五种**零 episode**（有意排除，非遗漏；代价照实登记：这些路径上用户的原始请求文本不入记忆）。挂起追问与首轮授权提示的抑制理由**完全一致**——追问既不是用户的输入、也不是系统的结论，写进去会让后续检索把它当成一条结论
- 云端多轮对话限制在有限回合内（最多3轮追问），不把控制权交给云端
- 云端每轮追问都须重新经过出站检查和入站检查
- 云端不直接产生可执行计划，只返回文本建议，由本地模型整合后决策
- **云端 provider 由用户配置选择（P6c 多云 Provider 最小底座，09 契约）**：活动 provider 是 grant/package/审计绑定的稳定标识（provider_id），由配置唯一决定，模型不得选择 provider；同一任务内 provider 固定，provider 切换后旧授权一律失效并重新确认。首批内置 `deepseek`、`glm` profile 与 `custom_openai`（HTTPS + 自配 model），统一经 OpenAI 兼容适配器输出同一 `AdvisoryResult`——安全授权、边界、审计与本地回流不因平台变化分叉
- **凭据 provider 专属**（09 契约 §4）：每 provider 使用专属凭据变量（`LOCALMIND_DEEPSEEK_API_KEY` / `LOCALMIND_GLM_API_KEY` / `LOCALMIND_CUSTOM_OPENAI_API_KEY`），禁止把一个通用 Key 无条件发送给任意 provider；凭据缺失 fail-closed 并点名应设置的变量；凭据读取留可替换接缝（产品化后可接系统凭据库，不改主循环与适配器协议）
- **云端失败可辨因**（09 契约 §6）：凭据无效、模型/端点配置错误、限流、传输故障、返回不合法分别映射稳定错误码，不再把 401 一律显示为「云端服务暂不可用」

### 🟢 FR2 渐进式理解

**描述**：不将所有历史上下文一次塞给模型。通过多轮按需检索，逐步逼近用户真实意图。

**要求**：
- 意图理解过程采用多轮认知循环（硬上限4轮）
- 每轮认知状态明确：VAGUE → PARTIAL → ALMOST → READY
- 每轮输出认知报告：已知信息、缺失信息、置信度、下一步动作
- 对检索结果执行差异化留存：打分后分为保留原文/保留摘要/丢弃
- 置信度驱动的分支策略需覆盖全部区间，不出现未定义空档
- 每一次模型调用只带最少必要上下文，无关内容不加载
- 上下文最小化作为独立职责，可被单独测试
- 模型只负责理解意图并输出置信度，最终调度决策由非模型的规则层执行
- **摘要不得扩张事实（2026-09-24）**：模型生成的滚动摘要与项目摘要是**推断**，不是事实；事实权威只有用户逐字陈述。要求三条：①摘要进入上下文注与外发任务包时带**确定性固定来源前缀**（自动生成 vs 用户手写，来源判定只读本地持久化的 `manual_overrides`，模型不可写），且与逐字检索片段的前缀**必须不同**；②生成提示词固定收窄为「只复述用户已陈述的内容与本轮实际发生的动作，不得推断结论、不得把未验证的推测写成事实，不确定的内容写成未解决事项」；③外发任务包中的「事实」section 只承载**用户逐字陈述**，摘要走独立的、带来源前缀的 section。摘要**不得强化**用户原话——「波形仿真完成、没有明显故障」不得变成「验证无故障」

### 🟢 FR3 安全护栏

**描述**：对输入和输出进行双向检查，防范危险信息泄露或执行。安全检查贯穿意图理解与工具执行两个阶段。

**要求**：
- **意图层面**：意图理解完成后，先校验意图本身是否危险，再进入执行阶段
- **执行层面**（高危操作——删除/修改/安装/网络外发/敏感读——触发三关）。**文件操作分级（2026-09-20 老板拍板反转 2026-09-10 的旧口径）**：**受限工作区内的一切 `file.write`——新建与覆盖一律进入确认链**（新建不再免确认）；**删除、移动及工作区外操作**仍属敏感或危险操作，走确认/拒绝链路。**反转理由（照实写明）**：旧口径的依据是「路径受工作区硬约束、新建破坏面小、试用体验优先」，当时不存在**概率性地选错工具**这条路径；P7a 引入能力路由后，模型的能力选择是概率判断，允许一次错误判断**直接改变文件系统**不适合作为基础 Agent 的默认行为——故把「写入」这一类动作统一放进用户确认（代价是「帮我写个文件」从一步变三步，这是**有意接受**的代价）。落地范围见 `specs/modules/16-p7-practical-tools-capability-routing.md` §11 第 21 项（**P7a-0 前置变更**）与 `clarifications.md` 的拍板登记；**P7a-0 落地前，任何报告不得声称该风险已覆盖**：
  - ① 相关性检查：操作目标是否在当前对话实体范围内？
  - ② 必要性+正确性：此操作真的需要吗？参数对吗？
  - ③ 身份确认：触发二次确认 + 口令验证（具体机制见 FR4）
- P0 阶段即提供 L1 硬规则保护（禁止路径、命令模式、敏感信息正则），不依赖 LLM；L2 语义检测后续通过 SafetyBackend 接口接入
- **出站检查**：敏感信息不得泄露到云端。检测判据与 FR1「凭据检测」条同一真源（含中文自然语言形态）；**任务包各 section 之间不得重复携带同一内容**（goal / 逐字事实 / 项目摘要 / 历史片段 / 证据各自去重，重复既放大字节预算也让用户在授权 preview 里看不出重点）——去重为**确定性文本规则**，不得交给模型改写
- **入站检查**：云端返回的指令，先验证再执行
- 三关逻辑在本地执行，不可被远端绕过
- 拒绝时给出明确原因，不静默阻断
- 所有外部副作用（文件、Shell、网络、云端调用）必须经过唯一的执行出口，任何模块不可绕过此出口直接调用底层能力
- 每次工具执行记录审计日志（操作内容脱敏、风险等级、判定结果、时间戳），供安全审查和问题回溯
- **工具候选必须结构化且落在运行时闭集内**（2026-09-18 明确，见模块契约 15）：模型提出的本地动作一律表达为「工具名 + 参数」的结构化草案；工具名必须来自运行时注册表（`ToolBackend.list_tools()`），参数必须按该工具声明的参数结构校验（成员、必填、类型）。工具名未知、参数不全或类型不符时**不得执行**，且必须给出显式失败或确定性追问，不得编造参数、不得静默降级为自然语言回答
- **完成性陈述只能来源于执行记录**（2026-09-18 明确，见模块契约 15）：任何「已创建 / 已覆盖 / 已删除 / 已执行」类陈述，只能由真实执行结果确定性构造，不得由模型自由文本产生；模型声明了本地动作而系统未能建立工具调用的回合，其可见回复必须是不经模型生成的确定性文案
- **文件类工具共用一条工作区边界**（2026-09-18 明确，见模块契约 15）：读取、列出目录、写入必须共用同一套路径解析与拒绝规则（绝对路径、盘符、UNC、`~`、工作区外逃逸一律拒绝），三条路径的边界行为一致；读不存在的目标返回统一错误，不得让原生异常逃逸到主循环

### 🔵 FR4 灵魂识别（探索阶段）

**描述**：通过行为特征判断操作者身份，危险操作触发二次验证。

**v1 范围**：
- 口令首次启动时设置，哈希存本地，不存明文
- 连续验证失败后锁定一段时间
- 行为特征仅做后台记录，v1 不作为放行依据

**远期探索**：
- 基于打字模式、工作时间、常用词汇等深度行为分析
- 累积可信度评分，高分免密，低分加验

### 🟢 FR5 自进化（接口保留，路线图暂不排期）

**描述**：基于经验教训自我改进，形成经验提取→模式聚合→技能生成的完整闭环。

> 2026-09-10 路线图调整：原 P8（自进化旁路）移出路线图，路线图在 P7 后暂时结束。EvolutionBackend 接口与 Noop 实现保留现状，待 Agent 真实使用暴露的问题决定是否推进。

**要求**：
- v1 阶段经验系统以旁路方式运行：只记录候选，不自动参与决策
- 核心闭环稳定后再接入经验自动提取和技能聚合
- 技能需有成熟度评估，不成熟技能不被采用
- 自动生成技能默认不自动执行，需人工审查通过后才可自动执行
- 低质量或被多次拒绝的技能自动淘汰
- 经验、技能可按意图检索，新任务时自动注入相关经验
- 远期预留模型内化（LoRA 微调）接口

### 🟢 FR6 话题切换与跨会话记忆

**描述**：支持用户突然切换话题；一个复杂项目横跨多次对话时，不重复发送全部历史。

**要求**：
- 检测话题切换：区分 same_topic / new_topic / shift_with_reference（切换但引用旧话题）/ ambiguous 四种关系
- 用户回到旧话题时，检索记忆按需加载
- Project-Conversation 两层数据模型：
  - 新对话开始只加载 Project 摘要（几十行结构化数据）
  - 需要细节时按 topic_tags 检索具体 Conversation chunks
- 每个对话有唯一 ID，可关联到项目

### 🟢 FR10 实用能力与能力路由（P7a）

**描述**：把「能力」作为工具之上的一层薄声明补进编排链路，让系统能表达「我有哪类能力」，并在没有对应能力时**诚实地说没有**；同时接入首个真实外部工具（天气），验证外部能力的扩展机制与网络出站边界。日常可用性提升不得以扩大副作用面为代价。

**要求**：
- **能力先于工具名**：运行时能力目录由 `ToolCapability{capability_id, summary, tools}` 声明；工具目录与能力目录都是**有界、稳定排序、逐轮显式校验**的闭集（工具 32 项 / 8192 字节；能力 8 项 / 2048 字节，超限 `CONFIG_ERROR` fail-loud，**禁止截断**）
- **「用户需要哪一类能力」与「该能力当前是否可用」分离（2026-09-22 新增，老板按真实 run 结论要求先改契约）**：模型只回答**需求侧**问题（本轮需要哪一类能力、或答「不需要能力」、或答「需要的能力不在目录里」），**不输出可用性结论**——**可用性是注册表的性质、由系统派生**（某能力声明的工具是否落在当前可用工具集内），模型既不能声称可用、也不能声称不可用。目录随之下传**声明的全量能力**（含当前不可用的），且**不标注可用性**：不标注是为了让模型按需求选择、而不是按「能不能用」自我审查（标注会让它改答「不需要能力」，把一个确定性的诚实失败换成一次自由文本作答）。由此「本地没有这个能力」的诚实失败是**注册表事实的确定性后果**，不再依赖模型猜注册表状态。**模型侧的负担与之相配地收窄**：理解结论（状态、缺失信息、风险档）由第一阶段一次给出，**第二阶段只要求工具与参数**（专用窄输出，不复述理解结论）
- **相关性有可测试的权威判定，但权威的边界是「能力约束」而非「请求语义」**：相关性 = 「草案工具 ∈ 模型所选能力的工具集」的**集合隶属**；权威是注册表里**作者声明**的能力—工具关系，**不是**模型的判断——同一个模型生成的 `intent_type` 与 `tool_call` 自洽**不构成**证据，也不得靠扫描最终中文回复判断。系统必须能区分「有匹配能力但参数不足」「没有匹配能力」「模型选了语义无关工具」三种情形。**口径纪律（2026-09-20 Codex 复审后收窄，对应 `16` §0.2/§0.3）**：本要求约束的是「**哪一类工具集合可能被执行**」，**不是**「所选能力是否真的匹配用户意图」——模型选错能力、而草案恰好落在所选集合内时**仍会执行**，本层结构上发现不了。该残余风险由三件事限制可达后果：①**只读能力**（`files.read`）的集合内工具全部只读；②**写能力**（`files.write`）按注册期不变式**独占该能力、且不得声明可补参**（对应 `16` §1.5 S1/S2），使「写工具缺参被下一轮输入填满」在注册期即不可达；③**外网工具**的入参值受来源与内容约束（见「网络出站边界」）。**⚠️ 诚实的边界（2026-09-20 复审更正）**：以上都是**结构性排除**，**不是**确认链兜底——本地写工具的危险档由**文件是否存在**在 preflight 决定（新建 = `normal` = **免确认直接执行**，见 `src/tools/registry.py:85` 与 `src/tools/file_tools.py:71`），因此「模型误选能力落到 `files.write`」这条路径**当前确实能在无确认的情况下新建文件**。该残余风险的封堵**已由老板 2026-09-20 拍板裁决**：`file.write` **一律进确认链**（新建与覆盖都确认），作为**独立前置变更 P7a-0** 落地（不并入能力层的编码批次，以便关/开对比可归因）。**P7a-0 落地前**，本 FR 与 `boss-report` **不得**声称该风险已覆盖（对应 `16` §11 第 21 条）。这是「**限制错误的可达后果**」，不是「发现错误」，不得据此宣称语义正确性
- **诚实失败**：无匹配能力时返回确定性 `capability_unavailable`，零工具执行、零完成性声明、零悬挂状态、不转云端（云端大模型**不等于**联网搜索，天气失败不得转为让云端猜实时数据），**不得**拿 `system.echo` 或文件工具兜底；`system.echo` 从生产/试用配置移除，仅保留测试用途（测试替身与生产能力目录分离）。**两类成因必须可分开观测（2026-09-22 补）**：①模型选中了一个**已声明但当前不可用**的能力（可修：配置/启用对应 provider）；②模型判定「请求需要外部实时数据，而**目录里没有能覆盖它的能力**」（要等工具生态扩展）。两者落同一个用户可见结论，但成因、处置与后续路线完全不同 ⇒ 必须在事件与报告里分列，不得合并成一个计数
- **缺参追问的续接是确定性机制，不依赖模型记住上一轮**：模型选出能力但参数不足时，系统把**整个候选**（含风险档与引用护栏结论）存为跨轮结构状态，下一回合把用户的补充回复**直接当作缺失参数值**，**零模型调用**（`rounds_used = 0`）送入既有校验链；该状态只在相邻一回合有效，消费即清、回合结束即清、会话结束即清。仅当「能力已路由 + 归属合法 + 恰好缺一项 + **该缺项在 `ToolDef` 里被声明为可直接补参 + 该工具未出现在写侧副作用清单中** + 无悬挂计划」时才建立；缺项 > 1 或校验层拒绝则**丢弃状态并回落正常模型路径**（fail-open-to-normal），**不得**让用户对着一个悬空状态反复补参数（对应 `16` §4.4）。**补参通道的可补参数是注册表声明式白名单**（`ToolDef.supply_by_echo: tuple[str, ...]`，P7a 只声明 `weather.current.location`）：下一回合的**整条用户输入**会被当作该参数的值，因此这是**唯一一处「用户文本直接进入工具入参」**的通道，**只有只读且入参外发可控的参数**允许开通（对应 `16` §1.5 S2）
- **「参数在、但值不是有效实例」是独立的失败格（2026-09-23 新增，S18 真实 run 暴露）**：模型可能**不省略**参数，而是把一段**逐字来自用户原文、却不是该参数有效取值**的文本填进去（真实复现：输入「今天天气怎么样」，模型把**整句**填进天气工具的地点参数）。此时既有的两级校验**都通过**——来源级判的是「这句话是不是用户说的」（是），执行级判的是「这段文本能不能发出去」（能）——于是**整句被外发**、工具失败，而应有的「追问缺参」从未发生。**本 FR 的立场**：参数值的**语义有效性**不由模型自述判定，也**不由 Core 内联的领域知识**判定，而是**由工具作者声明的判据**判定（声明住工具层，Core 只调用）；判定时机在**参数进入判定链之前**（准入级），因此「零外发 / 零完成性叙事 / 零云端咨询」是**结构性事实**，不依赖模型是否配合、也不依赖提示词质量。判定结论的处置是**把它当缺参**——追问 + 建立续接状态——**而不是**终端失败或执行失败：这是「用户说过、只是不是这个值」与「模型凭空造值」的分野（后者才是终端诚实失败，且**不可续接**）。**明令**：**不得**把领域词表（地名、时间词、疑问词）写进 Core 或配置（它会被当成可调开关而绕开注册期不变式，且中文词表当判据不可穷举）；**不得**由回复文本反推「这轮的值算不算地点」；**不得**靠加强提示词替代本判据（真实 run 已证明提示词加固无效——模型把判据当成了「复制原文」的执行细节）
- **首个真实工具仅 `weather.current`**：固定 HTTPS 天气服务（地理编码 + 当前天气/当日预报）；输入含地点，输出含标准化地点、观测/预报时间、天气、温度与来源；Provider 适配器可替换，Core 不依赖具体服务
- **网络出站边界**：固定允许主机 + HTTPS、禁重定向、连接与读取两段超时、响应字节上限、严格 JSON 解析、错误统一为项目错误；只发送完成查询所需的参数（地点），不发送会话、记忆、项目摘要或密钥；所有网络调用仍经唯一工具执行出口并产生**键名级**审计，不得绕过 `GuardedToolExecutor`；地点外发的告知语义是「事前无交互确认 + 事后可见（回复含地点与来源）+ 键名级审计」。**「只发送地点」是字段级与内容级双重约束（2026-09-20 复审后定稿，对应 `16` §6.3 第 4 条）**：出站请求体**除已验证的 `location` 外不携带任何其他原文内容**（会话、记忆、项目摘要、密钥一律不带）。`location` 的**值**出站前须过**三级**确定性校验，**三级分处两处、不可合并**（**2026-09-23 由两级扩为三级**）：**①准入级（来源，位于解析层）**——该值必须**整串逐字**（完整、连续、大小写与标点一致）地出现在**本回合用户输入**或**缺参追问后的补充回复**中，通过时该值**从用户原文中切片取得**（构造性保证，不是事后比对）；**判据是整串出现，禁止「≥2 字符重叠」这类弱判据**（否则「今天查天气」与「今天公司的内部项目」会在「今天」上误判通过）。不过则**不产生草案**：`tool_call_resolution = "param_not_from_input"` / `dispatch_decision.reason = "param_not_from_input"`，**零工具执行**（无 `tool_execution` 事件）。**②准入级（实例性，位于解析层同一点，2026-09-23 新增）**——该值还必须是该参数的**有效实例**：判据**由工具作者声明**（`ToolDef.param_instance_checks`），Core **只调用、不内置任何领域知识**（地名/时间词表一律住工具层）；通用的「值不得等于用户请求整句」这条规则**只对显式声明的参数生效**，且**只在准入级生效**（补参消费路径上「用户输入」就是那个值本身，在那里套用会误伤正确答案）。**判据是排除式、不是地名词典**（登记为残余：既非整句、也不在排除表内的短语仍可能被发出去一次；后果上界由固定主机、单字段、字节上限、零凭据、失败不转云端共同约束）。不过则**保留草案**（`tool_call_resolution` 仍 `resolved`）、**就地剔除该键**并记名（`intent_final.param_instance_rejected`），随后按既有参数校验走 `param_missing` ⇒ **向用户追问 + 建立缺参续接状态**（下一轮零模型调用续接）——**不是**终端失败、**不是**执行失败，**不新增任何错误码 / 理由值 / 能力结论值**。**③执行级（形态 + 秘密形态，位于工具 handler）**——形态（长度 1–64 字符、无控制字符、无 URL 元字符）与秘密形态（复用既有敏感值/裸密钥检测，**不新增第二套正则**）。不过则 `TOOL_EXEC_ERROR`，`details.reason = "location_rejected"`，**恰好一次 `tool_execution` 且 `outcome != "allowed"`**。**来源级与执行级仅以「是否存在 `tool_execution` 事件」区分**（实例级另有 `param_instance_rejected` 归因位），不得靠对同一字符串二次解析判别。任一级不过：**零字节离开本机、不转云端**。审计载体是**声明式**的（`ToolDef.audit_redact_all_params: bool = False`，天气工具为 `True`），该字段**不进入提示词的候选工具渲染**；`param_instance_checks` **同样不进提示词**（判据自身不得成为模型的可用信息）
- **风险与授权不变**：天气查询是用户显式请求触发的只读外部查询，默认 `normal` + 标准批准档；只升不降、三层校验、确认链、口令锁定、唯一出口全部不变；能力粒度的拒绝**不是**安全拒绝
- **非干扰性单列验收**：「天气功能关闭」（`tools.weather.provider="none"`，能力不存在）时，关键运行事件（动作、理解轮数、风险、上云准入、工具执行数）须与 P6 基线一致；**关态**（`capability_routing.enabled=false`）下**逐字段相等**是额外的工程锚点——但它**不是交付形态**（关态下能力层不参与，本 FR 的诚实失败与相关性边界都不成立），故 `config/default.toml` 的默认是**开启**，关态由运行器 `--capability-off` 构造；开态复跑 S01–S16（至少对 S05/S06/S09/S14 重复运行并比较结构化指标），**禁止**通过修改旧场景文本或放宽断言掩盖回归；不得把天气工具无条件塞进每一轮完整目录——纯问答、记忆检索、云端升级等回合不应看到它
- **阶段边界**：P7a 不实现任意 URL `web.fetch`、通用 `web.search`、Shell、Git、邮件/日历、MCP 市场或插件平台（动态能力声明涉及「谁能声明能力、声明如何被信任」的独立安全问题）；不顺带重构记忆、云端授权或主循环；不引入能力本体或第二套 Agent 框架
- **验收**：`16` §9 的 C1–C15（能力路由，含两阶段接线与跨轮缺参续接、**可用性派生与需求侧出口**、**阶段二窄输出与「第一阶段草案不可采信」**、**参数实例性判据与零外发**）+ W1–W10（天气与网络边界，含超时/畸形 JSON/重定向/超大响应/未知天气码/**出站值内容级与实例级校验**的确定性测试）+ 非干扰性五条 + S17（无能力诚实失败）/ S18（天气正常 / 缺地点→补充→续接（零模型调用）/ 未配置；**「缺地点」的两种形态——模型省略、或模型填了非实例值——都必须落同一结构化签名并同样能续接**，两形态仅在 `param_instance_rejected` 上可分列，**不得**因形态不同而让场景结论翻转）+ S01–S16 全回归；**S17 的口径（2026-09-22 写死）**：判据只在结构化观测上（分类字段、工具执行数、上云数、动作、关联理由），**文本断言只作辅助**；模型把实时需求误判成「不需要能力」（或选了与需求无关的能力）**算场景失败**，处置是**先改提示词再重跑**（不得改场景断言、不得改派生规则）；**禁止**用「回复里说了做不到」这类文本反推分类正确性；`weather_off` 臂**真实 run ≥ 3 次**并逐次记录能力分布的观测证据。真实 run 之前不得宣称「日常可用性达标」

### 🟢 FR11 工具生态接入底座（P7b）

- **目标不是一次接入大量工具，而是建立可扩展、可替换的通用工具接入底座，并用少量基础工具验证**。专家模型与自进化不在本阶段范围。
- **权威归属必须由代码结构回答（本轮的核心裁决）**：外部工具要能被用，必须先在**本地代码**里存在一条准入声明——规范名、所属能力、风险基线、批准档、副作用分类、参数契约（每个参数的来源约束与实例谓词）**全部本地签发**。外部来源（MCP 服务 / 插件）能提供的只有一件事实：「这个工具此刻存在」。**外部自报只能影响 `available`，永远不能影响 `allowed`**；MCP 的 `annotations`（含 `readOnlyHint`/`destructiveHint`）与 `description`/`inputSchema` 的任何文本**不读、不映射、不进判据**。**外部文本零进提示词**（进提示词的外部工具，其 `name`/`description`/`parameters` 全部本地撰写），因此**提示词字节账的上界不变**。
- **四条边界**：①**两阶段能力路由仍是唯一准入路径**——`[tool_providers]` 非空 且 能力层关闭 ⇒ **fail-loud**，使「绕过能力选择调用外部工具」不是一个被禁止的行为，而是一个**不存在的状态**；②**`GuardedToolExecutor` 仍是唯一执行出口**，插件与 MCP 服务不得直接产生副作用；③**动态变化只能朝收紧方向自动生效**（不热插拔、不自动重启、忽略 `tools/list_changed`）；④**外部工具不得自行降低风险等级、声明免确认或扩大可访问路径**——风险/批准档/副作用分类的唯一来源是本地声明，准入记录里**没有** `requires_confirmation` / `capability_id` / `preflight` 字段。
- **v1 的准入门槛（刻意收窄）**：副作用分类只允许 `read_only`（其它值 ⇒ fail-loud）；参数类型只允许 `string`（string 是唯一能同时受「整串逐字来自用户原文」与「作者声明的整值谓词」两级约束的类型）；transport **只有本地 stdio**（远端 transport 需要与 P7a §6 同级的独立出站论证，不在本阶段）。
- **「跑什么」由本地代码签发，配置只控制「跑不跑」（2026-09-26 修订，`17` 裁决 6）**：外部 provider 的可执行文件与固定参数写在**本地代码**的 `ProviderDeclaration` 里（`src/tools/provider_declarations.py`），配置里**只有** `enabled` 与两个超时（握手 / 调用），键集是**闭集**（多一个键即 CONFIG_ERROR）。**修订原因**：原稿允许配置提供任意命令，而这些进程在 bootstrap 阶段、**进入 `GuardedToolExecutor` 之前**就已启动——那条路径上的副作用不受唯一出口约束，与「配置只能控制传输、不能改变权限」在实现上不能同时成立。（另见本 FR 末尾的残余风险 ①：这是**可审查**，不是**沙箱**。）命令**永不经过 shell**（`shell=False` + argv 数组传参），因此 argv 元素**只禁无法构成进程参数的字符**（NUL / CR / LF、空串）；`;` `|` `&` 等 shell 元字符**是合法字符**，**不得**作为拒绝判据——理由：该禁令没有安全收益（`shell=False` + argv 数组传参已**结构性**消灭 shell 注入，**不存在一个 shell 去解释这些字符**），却会误伤合法路径（如安装目录本身含 `&`），并且会与「用含 `;`/`|` 的参数验证未被解释」这条验收臂**互相否定**。
- **外部工具的接入不改变任何既有架构边界（2026-09-26 据实修订）**：事件闭集（`_PERSISTED_KEYS` 与其独立副本）**零扩展**、`App` **构造签名**零变更、`ToolBackend` 接口**新增一个带默认实现的方法**（`close()`）——**两项零变更 + 一项必要变更**。`close()` 是**资源生命周期**所必需：`ToolProvider` 会启动子进程，而原稿的 `ToolProvider.close()` 没有任何调用方，进程没有确定性回收路径。编排层零改动。**P7a 的 R1–R8 / S1 / S2 与 `capability_relevance()` 集合隶属权威原样成立**——外部能力与内置能力**合并成同一份目录、跑同一套校验**。
- **进程级生命周期（2026-09-26 新增）**：`ToolBackend.close()`（默认 no-op、幂等、不抛异常）→ `CompositeToolBackend.close()`（关闭全部 provider，单个失败不阻断其余；关闭后 `list_tools()` 返回空、`execute()` 一律 `TOOL_NOT_FOUND`）→ **`App.shutdown()`**（新方法，委派给 `self.executor.tool_backend.close()`）；CLI、评估运行器与诊断脚本必须在 `finally` 中调用 `shutdown()`。**不得复用 `end_session()`**：那是**会话边界**，这是**进程边界**——挂在会话上会导致「另一会话仍在用的 provider 被关掉」与「从未开过会话的 provider 永不回收」。
- **子进程环境是白名单，不是继承（2026-09-26 新增）**：**禁止**把 `os.environ` 直接传给 `Popen(env=...)`（默认行为就是全量继承）。`env` 由**极小允许清单**构造：仅复制 Windows 必需的 `SystemRoot`/`windir`、`TEMP`/`TMP`、`PATHEXT`/`ComSpec`、`NUMBER_OF_PROCESSORS`/`PROCESSOR_ARCHITECTURE`，并自设 `PYTHONIOENCODING="utf-8"`、`PYTHONUTF8="1"`、`PYTHONDONTWRITEBYTECODE="1"`；**`PATH` 刻意不给**（`argv[0]` 已是绝对路径）。因此「子进程里没有凭据」是**结构性事实**（非白名单的键根本不存在），不是一句承诺。v1 无逐 provider 的环境注入。**子进程 stderr 钉为 `subprocess.DEVNULL`**（不是「丢弃或缓冲由实现决定」）：若实现成 `PIPE` 而**不持续消费**，大量 stderr 会写满管道缓冲区、子进程阻塞在 `write()` 上 ⇒ provider 卡死，且表现为「调用超时」这种**症状与病因错位**的形态。
- **超时即作废协议流（2026-09-26 新增）**：握手超时与调用超时都必须**终止子进程并标记该 provider 不可用**；超时发生后**不得复用同一条协议流**，也不得「继续读到 id 对上为止」抢救——迟到的响应会留在 stdout，被下一次请求当成自己的响应读走，再以 id 不匹配的形式报成协议错误（症状与病因错位）。这是一次**收紧**（动态变化仍只朝收紧方向生效），代价照实登记：一次偶发慢响应会让该 provider 在本会话内不可用。
- **帧结构逐方法区分 + 协议版本闭集（2026-09-26 新增）**：`initialize` / `tools/list` / `tools/call` 的响应结构**各不相同**——`result.content` **只属于 `tools/call`**（原稿把「缺 `result.content`」统一当协议错误，会在**正常握手**的 `initialize` 上直接判红）。必须钉住：支持的 `protocolVersion` 闭集（不在闭集内 ⇒ provider 不可用，不是 fail-loud）、逐方法的响应形状、响应 `id` ↔ 在途请求 `id` 的对应规则、`tools/call` 接受的 content 类型白名单（`text`；不支持的类型 ⇒ `provider_unsupported_content`，**provider 保持健康**——那是我们的能力缺口，不是链路坏了）与确定性的 `Result[dict]` 转换。兼容性检查同步加强：服务端顶层 `type == "object"`、本地必填参数在服务端存在且 `type == "string"`、服务端 `required` 不得含本地未声明的参数。
- **显示净化（2026-09-26 新增）**：工具结果进入 `display` 前必须剥离 Unicode `Cc`/`Cf`（保留 `\n`/`\t`），并设显示上限（超出显式标注截断）；**作用域是全部工具结果**，唯一实现点是 `ResponseBuilder.build()`（原始值合并进 `display` 的唯一位置）。原因：外部返回的文本会直接打到终端，ANSI CSI（清屏、移光标）、OSC 52（写剪贴板）、OSC 8（伪造超链接）都是**终端注入**，不是格式问题。`narrative_reply` / episode / 事件 / 审计 / 报告均**不受影响**（原始值不进持久面）。
- **必须明确处理的故障面**：工具名冲突、能力 ID 冲突、运行期增删工具、服务离线、超时、畸形响应、响应大小上限、秘密信息处理。**静态可判定**的问题（命令不存在、超时值非法、id 未登记、声明形态错）⇒ **fail-loud**；**动态外部事实**（进程起不来、握手超时、崩溃、协议破损）⇒ **「能力不可用」+ 诚实失败**，不得让本地 Agent 起不来，**也不新增 `degradation` 组件**（与 P7a 对天气失败同法）。
- **保持 `ToolBackend` 可替换**：内置工具、MCP、QwenPaw Skills 通过适配器接入，Core 不依赖具体平台。**QwenPaw Skills 按 `project-plan.md` 的定性即 MCP 标准** ⇒ v1 交付的是它的**接入点**——**2026-09-26 措辞修订**：这是**接入点 ≠ 已验证的接入**，本轮没有真实 QwenPaw / 第三方 MCP 服务参与互操作验证（演示服务是本项目自写的最小实现，不构成合规证明），**报告不得宣称「QwenPaw Skills 已接入」**；真实互操作测试登记为 `17` §11 第 12 项。原生 `skills_dir` 适配器与 ToolGuard L2 延后（触发条件见 `17` §11）。可替换性由**结构性证据**证明：聚合后端对 `mcp`/`qwenpaw`/`jsonrpc`/`subprocess` 零命中 + 一个「第三种 kind」的替身 provider 在 Core 零改动下走通全链路。
- **首批验证工具**：新增只读本地工具 `file.stat`（配新能力 `files.info`）与一个外部工具（经本地 stdio MCP 演示服务，配新能力 `text.format`）；`system.get_time` **复用不新增**；**不得重复实现已存在的天气与文件工具**。首批外部工具**刻意选纯函数式只读工具**。**2026-09-26 措辞修订**：原稿写「引入零新外发面」**不准确**——用户原文确实**离开 Agent 进程**进入 MCP 子进程，本契约自己也把它标为 `egress=True`。准确口径是：**没有新增网络或文件目标面，新增的是一个受控的本地进程出站面**。
- **照实写明的残余风险（不得宣称已覆盖）**：①**「只读」是本地作者的一个声明，不是系统可验证的事实**——外部工具是本机进程，系统无法约束它能读/能连什么，彻底缓解需要进程级沙箱（不在本阶段）；**2026-09-26 补强**：把命令挪进代码只让它**可审查**，不构成沙箱——provider 进程以**本机用户权限**运行，其启动、握手及运行期的自身副作用**不受 `GuardedToolExecutor` 约束**（该出口只能约束**工具调用**）。因此本阶段的准确称谓是「**受信任的已安装代码**」，且「外部工具不得直接产生副作用」这条边界（FR3）**对任意第三方 provider 不成立**，只在**本地代码显式声明过**的 provider 上成立。**不得**表述为「P7b 已解决插件安全」。②**外部工具没有目标级动态风险评估**（目标在外部进程内部，`preflight` 判不了）；③报告的 `available=false` **不区分**「provider 未启用」与「provider 已启用但离线」。**不得在任何面向用户的文档里宣称「MCP 工具是安全的」。**
- **阶段边界**：不实现任意 URL `web.fetch`、通用 `web.search`、Shell、Git、邮件/日历、远端 MCP transport、插件市场、零声明自动接入；不引入进程级沙箱；不顺带重构记忆、云端授权或主循环。**外部工具结果不得作为云端咨询的材料**（P7a §6.6 同纪律）。

### 🟢 FR12 本地文档读取与工作区搜索（P7c）

**描述**：把「读一份办公文档」与「在工作区里找东西」补成日常可用的本地只读能力。这两件事是用户每天都要做的事，而现有工具只能读 UTF-8 文本与列目录。本阶段**不介入联网搜索**，只做本地只读能力，且**日常可用性不得以扩大副作用面或泄漏面为代价**。

**要求**：
- **只做两个工具，且都是只读**：`document.read`（PDF/DOCX/XLSX/PPTX/TXT/Markdown，带来源定位的有界结构化文本）与 `file.search`（按文件名或文本内容搜索，返回匹配位置与有限上下文）。**不修改 `weather.current` 的任何行为**。
- **必须补一段通用的只读工具结果回流层（2026-09-27 老板审查后由"建议"升为"必须"）**：现状是「工具执行 → `ResponseBuilder` 直接显示 → 结束」，`ResponseBuilder` 最多显示 4096 字符且**全程无模型调用**（`src/core/response_builder.py` 的 `narrative_reply` 名字特判；③三条注册期不变式（RD1 闭集、**RD2 `model_summary` ⇒ 工具不在 `LOCAL_SIDE_EFFECT_TOOLS`** ⇒ 写入类工具继续确定性结果，**「让模型改写是否写入成功」是注册期不可达而非策略**、**RD3 `model_summary` ⇒ `egress=False`** ⇒ 回流不绕开 `17` **回落确定性显示**、`result_delivery="model_summary_failed"`、**不发 `degradation`**，工具结果永不因回流失败而丢失；⑦回流**不计入 `rounds_used`**（那是意图轮次的账），但必须经持久化键 `result_delivery` **可观测**；⑧`reply_provenance` 仍是 `"executed"`（回流是呈现层，工具确实执行了）；⑨**回流状态必须有载体到达事件层，且按 step_index 关联**——`ExecutionRecord` 追加尾部可选字段 `result_delivery: str | None = None`，回流返回的 `outcome.deliveries`（step_index → 值，见⑩）由 `_execution_records(plan, results, deliveries)` 按 **step_index** 回填；**不得按工具名关联**（同一计划可多次调用同名工具，按名字关联会把两条记录写成同一状态），**不得**用 `enumerate` 的列表下标当 step_index（`_execution_records` 内有 `continue` 过滤，列表下标与 step_index 不保证相等）。⑩**回流必须返回一个能同时承载「最终回复」与「覆盖状态」的结构**（2026-09-27 第三轮审查后钉死）——`ReflowOutcome(display: str, deliveries: Mapping[int, str])`：调用方要的是**一句回复文本**，而映射只带"哪些 step 走了模型摘要"，**装不下回复**（前版把返回类型写成 `Mapping[int, str]` ⇒ "回流算完了却没人拿到回复"，两处调用点只能各自再拼一次文本或丢弃模型输出）。**失败回落返回同一个结构** ⇒ 调用点**零分支**（`outcome = self._reflow(...)` → `return outcome.display`，**不得**出现 `if reflow_succeeded` 一类分支）。三态：无可回流 ⇒ `display` **逐字节等于** `ResponseBuilder` 的 `output.display` 且 `deliveries == {}`；成功 ⇒ 消毒+截断后的模型输出；失败 ⇒ **同样是那个 `output.display`**（**2026-09-27 第五轮订正**：①与③**共用同一份字节**，二者**只由 `deliveries` 区分**——回流层**永不自己合成回落文本**，因此"回流失败的用户可见后果与没有回流层时逐字节相同"是**构造性事实**，而不是靠实现自觉）。⑪**多 step 策略钉死：每回合至多一次回流模型调用**，覆盖集 = `results` 里出现、且其工具在**冻结目录**里声明 `model_summary` 的全部 step（⇒ 覆盖集内 `deliveries` 取值**必然相同**），输入按 **step_index 升序**组装、每段标注 `tool_name` + `step_index`、**共享同一份 `max_chars` 预算**（逐 step 调用会产生 N 个互相独立的候选文本，而一个回合只有一句回复；成本还随 step 数线性增长）。⑫**确认路径的回流输入必须是冻结的原始请求**（2026-09-27 第三轮审查后钉死，**安全相关**）——现有 `_pending_*` 字段**没有一个保存原始用户请求**，`_handle_confirmation(passphrase, session_id)` 的签名拿不到它，而确认回合的 `current_input` **就是确认口令**，且该回合**有意**用 `"[身份确认，原文不留存]"` 占位不保留原文 ⇒ 若取本回合输入，回流会把**口令**当成请求喂给模型，"总结这份文档"在确认路径上**结构性不成立**。裁决：`App` 新增私有字段 `_pending_user_request`，在计划**进入等待确认时**冻结；生命周期挂在**既有 `_clear_pending()` 上（清理点只有那一处，加一行）**，八条路径（取消/拒绝/会话不匹配/口令错误/锁定/预检失败/TOCTOU 变化/执行完成）全部覆盖；**必须在 `execute()` 之前先取出到局部变量**（`_clear_pending()` 在 `src/main.py:881` 先于执行发生）。**红线**：冻结值**只作回流输入**，**不得**进入 episode / 记忆 / 事件 / 审计 / 云端材料；`_record_turn("[身份确认，原文不留存]", …)` 的写法**保持不变**——P4 的"确认回合不留存原文"是既有安全口径，本轮**不放松**（"回流需要原文"≠"可以留存原文"）。本项目**没有**待确认计划的 TTL（不存在超时清理路径），若将来引入，冻结值必须与 `_pending_plan` **同生同死**。⑬**回流组件的两项必需输入按生命周期分流（2026-09-27 第五轮钉死，回应 Codex 在 RED 阶段提出的契约级缺口）**：**工具目录走构造期**——`ResultReflow(backend, tool_defs=tool_backend.list_tools(), enabled, max_chars)`，内部只提取 **name → `result_delivery`**。理由：`ExecutionStep` **没有** `result_delivery`，声明在 `ToolDef` 级，判据**无法从 `plan`/`results` 推出**；且目录在 bootstrap 后固定（`17`：不热插拔、不自动重启、只收紧），适合冻结，而目录来源与 `GuardedToolExecutor.execute()` 内部构造 `registered_tools` 的来源**同一个**（冻结集是可执行工具集的超集）。**不得**给 `ExecutionStep` 加该字段（会变成第三处签名变更，并把注册期事实复制进每一条步骤）。**确定性 display 走调用期**——`__call__(plan, results, original_request, fallback_display)`，调用点传 `output.display`：该值只有调用点手里有，回流层拿不到就只能**自己合成回落文本**（那是**第二份确定性显示实现**，两条路径的输出会分叉）。**回流层只读 `result_delivery` 这一个 `ToolDef` 字段**，不读 `risk_level`/`parameters`/`description`（准入与风控已由注册期与执行器负责，再判一次就是**第二份准入真源**）；目录里**查不到**的工具名按 `deterministic` 处理、**不抛错**（该分支不可达，且回流是呈现层，"少一个声明"不该让已成功执行的回合失败）。**关态**（未注入或 `enabled=false`）⇒ `ReflowOutcome(display=fallback_display, deliveries={})`，两种来源**行为等价**，两个调用点仍写成**零分支一行**。**"成功"是构造性事实而非运行时判据**：`GuardedToolExecutor.execute()` 在七条失败路径上**全部 `raise`**（未注册/参数被拒/`dangerous`/`high_impact`/敏感未确认/策略拒绝/工具返回错误），`results` **只含成功步骤**、结果 dict 里**没有** `outcome` 字段（`_execution_records` 里的 `outcome="success"` 是硬编码）⇒ 实现**不得**去找"成功标志"。**执行抛错 ⇒ 零回流**（`output` 都没构造，没有 `fallback_display`；**部分成功的中间结果不做事后回流**——那是"部分成功语义"，本阶段明确不做）。**本回合的 `_execution_records` 有** **三个**调用点（`src/main.py:885` 事件用、**`:893` episode 用**、`1020` 直连路径），**必须传同一份 `outcome.deliveries`**——只给事件侧传值会让 episode 记录退化成 `None`，同一事实在两处不一致。
- **回流层对提示词注入的承诺必须写成"后果上界"，不得写成"已解决"**：结构的成立部分是**「注入不产生动作」**——回流输出只被当作给用户看的文本消费，**不进入** `ToolCallDraft`/`intent_type` 解析、**不触发**工具执行/确认/授权/云端准入、**不成为**云端材料（`result_reflow.py` 零解析层、零 `src/cloud/` 导入，源级断言）；**注入能改变用户读到的文字**这一点无法结构消除，登记为残余。**不得**表述为「文档内容已安全」。
- **回流的输入预算是字符预算，是对 token 预算的粗略代理**（本地模型上下文默认 4096 token，`src/models/ollama_backend.py:21`）：`[reflow].max_chars`（默认 4000）**小于**工具自身的 `max_returned_chars`（40000）。**`max_returned_chars` 的作用域必须照实写明（2026-09-27 审查后订正）**：**原始工具结果不持久化**（`ExecutionRecord` 只存字段名摘要，`_execution_summary` 明确 "without retaining any returned value"），因此 **`max_returned_chars` 是执行期内存上限**，其真实消费者只有回流与回落显示两个；默认口径下 40000 里的绝大部分**既不进模型也不进显示**，随回合结束丢弃。**不得**再表述为"用于执行记录的可审计留存"。**回流无调用级超时**（`ModelBackend.generate()` 无该参数，后端超时在构造期固定）⇒ 回流**沿用后端自身超时**，**不得**用"线程等待 N 秒后放弃"实现（放弃等待不取消底层 HTTP 请求，会累积后台线程；以零 `threading`/`Timer`/`concurrent.futures` 导入作源级断言）。「回流输入被模型截断」「按 token 精确切分」「调用级超时扩展」「回流输出上限与显示上限解耦」均登记为遗留项。
- **回流的输出与输入用同一份消毒实现、同一个长度上限（2026-09-27 审查后钉死）**：回流成功时 `reflow()` 的返回值**直接作为最终文本**，**不经过** `ResponseBuilder.build()` ⇒ **模型输出的净化与长度上限必须由回流自己施加**：①把 `ResponseBuilder` 的模块私有 `_sanitize_display_string` 提升为**公开** `sanitize_display_text()`，②把 `_DISPLAY_LIMIT` 提升为**公开** `DISPLAY_LIMIT`，回流输入与回流模型输出**都**过前者、输出另截到后者。**为什么这仍是安全边界**：模型可能**原样复述**文档字节，文档里的 ANSI/控制字符因此有机会经"模型复述"落到终端（与 `17` 已就外部工具结果立过的终端注入同类）。**必须实测**：替身模型返回 ANSI/`Cc`/`Cf` 字符 ⇒ CLI 捕获的输出里**不得**出现这些码点。
- **明确不做**：通用 `web.search`、任意 URL `web.fetch`、Tavily/SearXNG/任何搜索 provider 与 API Key、OCR、扫描型 PDF、文档编辑与格式转换、内容索引/向量化、旧格式 `.doc`/`.xls`/`.ppt`（与 FR10/FR11 的阶段边界一致，`16` §11 第 1/2 项）。
- **接入路径复用既有链路，零主循环特判**：两个工具经 `ToolBackend` → 能力路由 → `validate_tool_call()` → `ControlPolicy` → `preflight` → `GuardedToolExecutor` 接入；`App` 主循环、`ControlPolicy`、`TaskPlanner`、`GuardedToolExecutor` 内**不得出现工具名字面量**（含回流层的判据：必须读 `ToolDef.result_delivery`，不得按名字分支）；`ToolContext` / `ToolHandler` / `ToolBackend` 构造签名与 **`bootstrap()` 的签名**均不动，上限经**闭包工厂**注入（沿用 `16` §5.3 已就天气工具钉死的解法）；**但 `bootstrap()` 内部新增一步装配**（构造 `ResultReflow` 并注入 `App`）——**"签名零变更"不等于"函数体零变更"**，只改 `App.__init__` 的签名而不在此构造，生产环境不会启用回流（第四轮阻塞项，见下决策表）。**接口签名变更恰好两处**（**均为追加式尾部带默认值 ⇒ 既有构造调用零改动**）：`ToolDef.result_delivery: str = "deterministic"` 与 `ExecutionRecord.result_delivery: str | None = None`。另有**一处新增 Core 类型**（非既有签名变更，但跨组件可见，同属 Claude 主导的接口面）：`ReflowOutcome(display, deliveries)`（见上条⑩）。另有两处**"私有 → 公开"提升**（非接口签名变更，但主流程依赖）：`sanitize_display_text()` / `DISPLAY_LIMIT`。**主流程变更恰好三处**：①两个 `response.build` 调用点插入共享 `reflow()` 并排到 `_record_tool_events()` 之前；②`_execution_records(plan, results, deliveries)` 新增第三个参数；③`App` 新增一个注入口（`reflow`，追加置尾带默认值）与一个私有状态项 `_pending_user_request`。**另加 `bootstrap()` 内的一步装配**（构造 `ResultReflow` + 传入 `App`，签名不变）。**因此"App 零变更"与"`bootstrap()` 步骤零新增"两条结论均作废，照实写明**。替换解析库或搜索实现时**不得**修改意图理解与主循环。
- **路径安全复用，不重定义**：唯一解析器仍是 `resolve_workspace_target`（`15` §6.1），**不得**在 P7c 内新增任何路径判据；逃逸 ⇒ `FILE_ERROR` + preflight `effective_risk="dangerous"` 硬拒。**搜索独有一个新口子必须堵**：`resolve_workspace_target` 只保护**搜索根**，不保护**遍历中遇到的软链接** ⇒ ①**两个引擎都不跟随任何符号链接**——不得传 `-L`/`--follow`；降级引擎 `followlinks=False` **且显式跳过文件符号链接**（`os.walk` 在 `followlinks=False` 下**仍会把指向文件的符号链接放进 `filenames`**、`open()` **会跟随它**读到工作区外——这是必须连文件符号链接一起跳过的真实理由）；②**每条结果在入集前经一次包含性复检**，越界即丢弃并计数 + `notice`（不得静默丢弃）。**复检的定位必须照实写明**：既然两个引擎都不产出符号链接目标的候选，复检在常规遍历中**不可达**，它是**纵深防御**（覆盖 TOCTOU 与被遍历/被读取之间的替换、以及不受本契约控制的外部二进制默认值漂移），其验收**必须靠注入伪造候选**，**不得**宣称"靠复检拦住了 N 次越界"。「模型不能通过搜索参数绕过工作区边界」的成立依据是**候选集永远是工作区内的有限集合**这一构造，不是参数黑名单。
- **有界且不得静默丢失**：`document.read` 设五重上限（文件大小 / 提取字符数 / 提取段数 / 返回段数 / 返回字符数），`file.search` 设五重上限（匹配总数 / 单文件匹配数 / 行长 / 上下文行数 / 超时）。**上限只能来自配置，不得设模型可调的读取范围或长度参数** ⇒「模型放大自己的读取预算」不是被拦截的行为，而是**不存在的状态**。超限时必须**明确告知未返回的数量**（`notice` + `segments_total`）；**总数未知时必须为 `null`，不得用猜测值或 `len()` 冒充**；**`truncation_reason` 闭集必须包含 `max_extracted_chars`，且"哪个提取上限先命中就记录哪个"**（把字符上限记成段数上限会说出"在 20000 段处停止"这种**事实错误**）；**`chars_extracted` 是"实际已提取字符数"，不是文档总字符数**（提取中途停止时它是下界，此时**不设**总量字段——一个恒等于它或恒为 `null` 的字段没有信息量，诚实性由"下界 + 截断原因 + 未返回量说明"三者共同承载）；**"至少返回一段"只适用于 `extraction="ok"` 的非空文档，不适用于空文档与无文本层 PDF**（后者 `segments=[]` 是正确结果，不得为凑数塞占位段）。另需**在解析器拿到文件之前**限制 OOXML 的 **ZIP 条目数与总解压大小**（10 MB 的压缩包可合法展开成数 GB）。
- **成功与失败的界线按事实划**：**空文档与扫描型 PDF 都是成功**（`extraction="empty"` / `"no_text_layer"` + `notice`），**不是错误**——做成错误会让模型的可用信息退化为"工具坏了"，而正确结论是"这份文档里没有可读文字"。反之**空查询必须失败**（`query_invalid`，零结果）——返回空结果集会让模型**如实说出错误结论**（"工作区里没有 X"），而真相是"没有搜"。
- **依赖策略：四个解析库是正常依赖，不是可选 extra（2026-09-27 老板裁决，前版"optional extra"的推导作废）**：P7c 是**默认启用的日常能力**，"支持 PDF/DOCX"却让首次使用普遍得到 `parser_unavailable` 是**产品缺陷**，不是诚实。原推导「因为要求明确依赖缺失时的行为，所以依赖必须是 extra」**不成立**——即使列为正常依赖，**安装损坏 / 部分安装 / 打包剥离**仍会产生"模块不存在"这一事实。因此：文档格式解析采用**成熟库**（`pypdf` / `python-docx` / `openpyxl` / `python-pptx`）并列入 `[project.dependencies]`（**2026-09-27 老板已授权本阶段修改 `pyproject.toml`**），**不自行实现** Office/PDF 解析器；TXT/Markdown 零依赖仍可用；**缺依赖逐格式独立判定**（只影响该格式）且**不得影响应用启动**（依赖检查必须在分派时、不得模块级 import）⇒ 缺依赖仍是 `parser_unavailable` 的诚实失败，不是崩溃。**逐格式提取范围必须写进契约与 `ToolDef.description`**（不钉死则实现会自行猜测）：DOCX 读正文段落 + 全部表格（`table_row` 段），**不读**页眉/页脚/脚注/批注；XLSX 用 `read_only=True` + **`data_only=False`（返回公式文本）**——缓存值由 Excel 写入，**从未被 Excel 打开过的文件缓存值为空**，`data_only=True` 会**静默丢失公式结果**；PPTX 读文本 + 表格（并入幻灯片段），**不读**备注。ripgrep **不是** Python 依赖，也不写入 `pyproject.toml`。

成立）；④「提示词注入已解决」（结构成立的是**注入不产生动作**；注入改变用户读到的文字**仍是残余**）；⑤**「回流有超时保护」**——回流沿用**模型后端自身的**超时（后端构造值，默认 120 s），本阶段**不承诺**单次回流的延迟上界，也**不得**用"线程等待 N 秒后放弃"伪造（放弃等待不取消底层请求，会把线程泄漏伪装成超时）；⑥**「确认路径的回流输入已在真实 run 里验证过」**——场景层能观测的只有事件与输出，**提示词是私有输入、不进事件、不进持久面**，因此"S20 通过"证明的是**可观测后果**（口令未出现在用户可见输出里），提示内容本身只由 **R16** 的替身模型覆盖；把两者混为一谈即为过度宣称；⑦**「回流层验收通过 ⇒ 文档总结在生产配置下可用」**——`reflow` 是**带默认值的追加参数**，而 R1–R18 都可以用"直接构造 `App(reflow=替身)`"满足 ⇒ **它们全绿与"生产环境启用了回流"之间没有蕴含关系**。该蕴含只由 **R19**（走 `bootstrap()`）承担；"接口加了参数"与"装配处传了参数"是两件事，**凡新增带默认值的可注入组件都必须分别验收**。

## 二、非功能需求

### 🟢 NFR1 硬件约束

- 目标环境：普通办公电脑，16GB RAM，无独立显卡
- 模型推理：CPU 推理为主
- 内存峰值：< 12GB（需留 4GB 给系统和常用办公软件）
- 存储：向量库 + 模型文件 + 对话数据 < 20GB

### 🟢 NFR2 性能要求

- 模型冷启动（加载到内存）：目标 5-15 秒，最低可接受 30 秒
- 热推理速度：目标 ≥ 10 token/s（CPU），最低可接受 5 token/s
- 意图理解循环：目标单轮 < 3 秒，最低可接受 8 秒
- 工具执行：Shell 命令 < 5 秒返回
- 调试模式允许加详细日志，性能指标可单独放宽

### 🟢 NFR3 技术约束

- 推理引擎：使用 Ollama（优先）或 LM Studio，不自研
- 技能系统：遵循 MCP（Model Context Protocol）工具标准
- 复用方式：能直接用的直接拿 → 能改改用的就改改用 → 能外部调用的就外部调用
- 开源协议：遵守所有复用组件的许可证

### 🟢 NFR4 架构约束

- 主循环自研，调用各模块，模块间低耦合
- 分阶段交付，每个阶段有可运行、可验证的产出
- 不追求一步到位，核心功能跑通后再优化
- 明确 Core-owned 和 Adapter-owned 边界：外部组件不可反向决定核心模块的数据模型和控制流
- 增强能力（云端、多专家、自进化）在核心闭环稳定前只留接口，不进入主路径
- Core 代码不 import 具体后端（ollama / qwenpaw / everos / turbo_llm），只依赖抽象接口
- 所有 Adapter 由配置创建并依赖注入，Core 不手动实例化具体实现
- P0 测试必须用 MockBackend 跑通全部核心闭环
